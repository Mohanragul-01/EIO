# Notes v3 Implementation Plan

**Goal:** Spec §6 in full on the phone and the website: a recoverable Trash with undo, pins, archive, note colours, Markdown read mode with tickable `- [ ]` boxes and a formatting bar, a journal that rewards re-reading (On this day, streak, prompt), checklist upgrades, a smarter create button, and long-press selection — without a trashed note ever appearing anywhere it used to be counted.

**Architecture:** One migration (`0021_notes_v3.sql`) adds four nullable columns. Every rule lives in pure TypeScript inside `app/src/modules/notes/`, each file with tests, and both clients import it: `library.ts` (what is live, which tab shows what, pinned split, search, tag counts, purge window), `markdown.ts` (the hand-written parser, preview stripping, checkbox toggling), `markdownEdit.ts` (formatting-bar edits and Enter-continues-a-list), `journal.ts` (On this day, streak, week strip, prompts), checklist helpers in `types.ts`, and `noteColors.ts`. `api.ts` is the only database code. The phone list moves from four per-tab queries to one query for every live note, from which each tab is derived — so a pin, a trash or an undo in one tab is instantly right in all of them.

**Spec:** `docs/superpowers/specs/2026-10-19-eio-v3-design.md` §6 (binding), §2, §3, §12. Evidence: `docs/research/notes.md` (§5 recommendations, §6 UI patterns).

## Global constraints

- §2 in full: 48dp targets, never colour alone, Ionicons / `Icon.tsx` only, no card swipes (the list is in the tab pager — long-press instead), undo for trash/archive/uncheck-all/delete-ticked, confirm only Delete forever and Empty trash, semantic tokens only, a11y labels and states, light and dark.
- **Trash is invisible everywhere it is not the Trash.** Every read on both clients goes through a query or a pure filter that excludes `deleted_at is not null` (and, outside the Archive, `archived_at is not null`).
- Toasts are shown after a sheet closes or a screen is left, never from inside a sheet.
- Website reuses `@app/modules/notes/*`; no rule is written twice.
- Checks after every task touching shared code: app `tsc`, `eslint src App.tsx`, `jest`; website `tsc -b`, `eslint src`, `vite build`.

## Every read of `notes`, and how it excludes the Trash

Found with `grep -rn "notes/api\|notesOverview\|listNotes\|listInbox\|listJournal\|listChecklists\|from('notes')"` over `app/src` and `website/src`:

| Reader | Before | After |
|---|---|---|
| `app/src/modules/notes/api.ts` `listNotes` / `listInbox` / `listChecklists` / `listJournal` (four phone tabs) | every row of the type | replaced by `listLive()`: `deleted_at is null and archived_at is null`; tabs derived by `viewNotes()` which re-checks `isLive()` |
| `api.notesOverview` → `app/src/home/useHomeSummaries.ts` and `website/src/pages/Dashboard.tsx` (both home tiles) | every row | `deleted_at is null and archived_at is null` in SQL, counts by the pure `overviewCounts()` which re-checks |
| `useNotes` `allTags` (phone tag chips) | all loaded rows | `tagCounts()` over the live rows |
| `useNotes` `visibleNotes` (phone search) | all loaded rows | `filterNotes()` over the live rows |
| `website/src/pages/NotesPage.tsx` load (`listNotes` + `listJournal`) → counts, tag counts, search, Inbox filter | every row | `listLive()`; counts / tags / search go through `viewNotes`, `tagCounts`, `filterNotes` |
| `api.getNote` (edit screen) | one row by id | unchanged; a trashed note opened from a stale screen shows read-only with Restore |
| New: `listTrash()`, `listArchive()` | — | the only reads that return trashed / archived rows |

Pure-filter tests prove a trashed (and an archived) row is dropped by `viewNotes` for every tab, by `tagCounts`, `filterNotes` and `overviewCounts`.

## Tasks

### N1 — Plan (this file). Commit.

### N2 — Migration `supabase/migrations/0021_notes_v3.sql`
- `deleted_at timestamptz`, `pinned_at timestamptz`, `archived_at timestamptz`, `color text` with a guarded check (`null` or one of the seven keys).
- Partial index for the live list: `(user_id, updated_at desc) where deleted_at is null`; one for the Trash: `(user_id, deleted_at) where deleted_at is not null`.
- `notes_touch_updated_at()` replaces the generic trigger on `notes` only: `updated_at` moves only when content changes (title, body, tags, type, inbox flag, entry date, checklist), so pin / colour / archive / trash / restore never reorder a list and Undo puts a note back exactly where it was.
- Idempotent (`add column if not exists`, guarded `do $$` for the check, `drop trigger if exists`). Drops nothing v2 reads. Needs 0003 and 0010 first.

### N3 — Lifecycle and views: `library.ts` + `__tests__/library.test.ts`
- `Note` gains `deleted_at`, `pinned_at`, `archived_at`, `color` (types.ts).
- `isLive(note)`, `isTrashed`, `isArchived`; `TRASH_DAYS = 30`; `purgeCutoff(now)`; `daysUntilPurge(deletedAt, now)`.
- `viewNotes(notes, view)` for `notes | inbox | checklist | journal` (type filter + each tab's existing sort, live only).

- Tests: a trashed and an archived note never appear in any tab, tag count, search or overview; pinning keeps an inbox note in the Inbox; purge countdown across a DST change.

### N4 — Markdown: `markdown.ts` + `__tests__/markdown.test.ts`
- `parseMarkdown(body): Block[]` — heading 1–3, paragraph, bullet, numbered, task (`- [ ]`, `- [x]`, `* [ ]`, bare `[ ]`/`[]`), quote, blank; indent depth; each block keeps its source `line`.
- `parseInline(text): Span[]` — `**bold**`/`__bold__`, `*italic*`/`_italic_` (not inside words), `[text](url)`, bare `https://` / `www.` links, backslash escapes; unclosed markers stay literal.
- `safeHref(url)` — only http(s) and mailto.
- `stripMarkdown(body)` — previews without syntax, one line per source line.
- `toggleTask(body, line)`; `taskProgress(body)`.

### N5 — Editing: `markdownEdit.ts` + `__tests__/markdownEdit.test.ts`

- `wrapSelection(text, selection, marker)` for bold / italic (toggles off when already wrapped; empty selection puts the cursor between the markers).
- `insertLink(text, selection)` — `[selected](https://)` with the cursor on the URL.

## Rulings

- **Ruling: purge on open, not on a schedule** — when the Notes screen, the Trash or the website's Notes page opens, rows trashed more than 30 days ago are hard-deleted by `purgeExpiredTrash`. pg_cron may not be enabled and cannot be verified from here; a purge on read needs nothing. — Cost if wrong: a trashed note can outlive 30 days if Notes is never opened, which loses nothing.
- **Ruling: `updated_at` moves only on content changes** — a notes-only trigger ignores pin, colour, archive and trash. Otherwise Undo after "Moved to Trash" would put the note back at the top of the list rather than where it was, and pinning would read as an edit. — Cost if wrong: colour or pin changes no longer count as "recently touched", which is the intent.
- **Ruling: one query for every live note** — `listLive()` replaces the four per-tab queries; the tabs are pure derivations. The pager mounts all four tabs anyway (so the old design fetched most rows twice), and selection, pin and trash cross tabs: one array keeps an action and its undo right in every tab at once. — Cost if wrong: thousands of notes would make the single fetch slow; the fix is paging in `api.ts` only.
- **Ruling: archived notes leave every tab, search and the home tile's counts** — "done with it, keep it". The Archive view lists them. Trashing an archived note keeps `archived_at`, so Restore returns it to the Archive. — Cost if wrong: someone expecting archived notes in search has to open the Archive.
- **Ruling: pinned order is most recently pinned first** — stable, and needs no reorder UI. The Journal tab has no Pinned section (it is chronological and has On this day for re-reading); a pinned entry shows its pin glyph in its day. — Cost if wrong: a pinned journal entry is not hoisted.
- **Ruling: streak counts consecutive days with an entry, ending today — or yesterday while today is unwritten; backdated entries count** — the day was journaled, and the research leaves this open. Trashed and archived entries do not count. — Cost if wrong: a backdated entry can repair a broken streak.
- **Ruling: On this day on 28 Feb of a non-leap year includes 29 Feb entries** — otherwise they would surface once every four years. — Cost if wrong: one extra card on 28 Feb.
- **Ruling: prompts are a static list of 40, chosen by date, with shuffle stepping through the list** — stable for the day, no network, no AI. Answer opens a new entry with the prompt as a quote on the first line. — Cost if wrong: prompts repeat every 40 days.
- **Ruling: seven note colours, stored as a key** (`red`, `orange`, `yellow`, `green`, `teal`, `blue`, `purple`), each one mid-tone swatch used on both themes as the category colours are — tint at ~14% and a 3px edge stripe, text colour unchanged so contrast holds. Unknown keys render as no colour. Stored as a key, not hex, so swatches can be retuned without a migration. — Cost if wrong: a swatch might read slightly differently on light vs dark.
- **Ruling: the Markdown subset** — `#`/`##`/`###`, `**bold**`/`__bold__`, `*italic*`/`_italic_` (an underscore inside a word stays literal, so `snake_case` survives), `-`/`*`/`+` bullets, `1.`/`1)` numbers, `>` quotes, `[text](url)` and bare http(s)/`www.` links, `- [ ]`/`- [x]` and bare `[ ]`/`[]` tasks (Notion's typed shortcut). Links are limited to http(s) and mailto: a `javascript:` link would run on the website. No code, tables, images, strikethrough. — Cost if wrong: someone typing other Markdown sees it literally.
- **Ruling: the ticked group is a view, not a reorder** — the stored order never changes, so unticking returns an item to its place; the group is collapsed by default ("in a shop you want only what's left"). — Cost if wrong: one tap to expand.
- **Ruling: Uncheck all and Delete ticked act immediately in read mode, with an undo toast** — they are the reusable-list gestures and belong where ticks already save. Edit mode keeps a buffered Uncheck all (Discard covers it). — Cost if wrong: none found.
- **Ruling: pin, colour and archive write immediately** (read mode, selection mode, website card actions), never through the edit form, like ticks. — Cost if wrong: they cannot be "discarded".
- **Ruling: `deleteForever` only deletes rows already in the Trash** (`deleted_at is not null` in the query), so no bug can hard-delete a live note. — Cost if wrong: none.
- **Ruling: Trash cards are read-only** (Notion): tap opens Restore / Delete forever. A trashed note reached any other way opens read-only with Restore. — Cost if wrong: one extra tap to edit a trashed note.
- **Ruling: the create button on Inbox is quick capture** — the Inbox is where quick captures land, so that is its "type"; the separate quick-capture button is hidden there as redundant. Journal opens today's entry when one exists (the most recently created if several). — Cost if wrong: a full note from the Inbox is one long-press away.
- **Ruling: the formatting bar is a `KeyboardStickyView`, not `KeyboardToolbar`** — the toolbar is 42dp tall with Prev/Next arrows we do not need; the sticky view rides the keyboard the same way and lets the buttons be 48dp. Shown only while the body field is focused and the keyboard is open. — Cost if wrong: none expected; both come from the installed library.
- **Ruling: selection mode is phone-only** — the website has a pointer, so each card carries hover actions (Pin, Colour, Archive, Trash) instead of a long-press. — Cost if wrong: no bulk actions on the web.
- **Ruling: selection mode exits after any action, on Back, and when the tab changes** — a selection is about the cards you can see. — Cost if wrong: re-selecting after a colour change.
