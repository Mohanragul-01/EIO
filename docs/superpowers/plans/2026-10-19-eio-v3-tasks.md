# EIO v3 — Tasks: implementation plan

*19 Oct 2026. Builds spec §5 (`docs/superpowers/specs/2026-10-19-eio-v3-design.md`) on branch `v3-tasks`. Evidence and UI patterns: `docs/research/tasks.md` §5–§6.*

## Goal

Make Tasks answer "what do I do now?" on the phone, and make repeating responsibilities — most of this person's list — behave correctly. Fix the three confirmed recurrence bugs first, each pinned by a failing test, then build: a Today view as the phone's default, a real recurrence engine, time + reminders with Done/Snooze and a daily digest, a hand-written day-first quick-add parser, complete-with-undo and a long-press menu, notes and a resetting checklist, streaks and per-routine history, and on the website Group by, overdue counts, the same quick add and a month calendar.

## Tasks (build order)

1. **Migration `0020_tasks_v3.sql`.** Columns: `due_time time`, `reminder_offset_min int` (0–10080), `repeat_every smallint default 1` (1–366), `repeat_weekdays smallint[]` (0–6), `repeat_anchor_day smallint` (1–31), `repeat_nth smallint` (1–4 or −1), `repeat_from text default 'due'` (`due|completion`), `series_id uuid`, `completed_at timestamptz`, `outcome text` (`done|skipped|wont_do`), `notes text default ''`, `checklist jsonb default '[]'` (array). Backfills, in this order: `completed_at = updated_at`, `outcome = 'done'` for done rows; anchor day from the due date for monthly/yearly repeats; `series_id` grouped by (user, trimmed lower title) for repeating rows. Indexes: `(user_id, series_id, due_date)`, `(user_id, completed_at)`. No trigger, nothing dropped.
2. **Bug 1 — overdue repeats pile up.** Test: `nextDueDate('2026-08-01', rule daily, { today: '2026-08-22' })` is `'2026-08-23'`, and a weekly Monday task overdue three weeks lands on the next Monday after today. Fails against v2 (returns `2026-08-02`). Fix: `recurrence.ts` rolls forward with `stepOnce` until the date is after today.
3. **Bug 2 — month-end drift.** Test: monthly anchored on 31 from `2026-02-28` gives `2026-03-31`; yearly anchored 29 Feb returns to 29 Feb in a leap year. Fails against v2 (`2026-03-28`). Fix: `stepOnce` clamps the stored anchor day, never the previous date.
4. **Bug 3 — reopening duplicates.** Test (`api.test.ts`, in-memory fake Supabase): complete a repeating task, reopen it → exactly one open row in the series, and the reopened row is it; a successor that was edited is kept. Fails against v2 (two open rows). Fix: `series_id` on successors, `reopenTask(todo)` deletes the series' untouched open occurrences after reopening (write first, delete last).
5. **Recurrence engine** (`recurrence.test.ts`): every N; weekly weekdays incl. every 2 weeks on Mon+Thu; monthly day N / nth weekday / last day; yearly; from-completion; `isSchedulePoint`, `alignOnOrAfter`; `upcomingDates` (next three); `describeRule` / `shortRule` wording; DST-safe (tests run in New York).
6. **Skip / won't do / complete** in api with outcome + `completed_at`; successor carries the rule, time, reminder, notes, and the checklist reset to unticked. Tests in `api.test.ts`.
7. **Quick-add parser** (`quickAdd.test.ts`, exhaustive): today/tomorrow/weekday/next weekday/next week/next month/weekend/in N units; day-first numeric dates (19/10, 19-10-26, 19.10.2026, 2026-10-19), month names both orders, rollover to next year, invalid dates left as text; times (7pm, 7:30 pm, 19:00, noon, at 7 → nearest future); repeats (daily, every day, every other day, every 3 days, weekly, every mon[,/and] thu, every weekday, every weekend, every 2 weeks, monthly, every 15th, every 2nd sat, every last fri, yearly, every! 3 days, after 10 days); priority (!high/!h/!1/p1 …); connectors (on/at/by/due) absorbed; first-of-kind wins; ignored tokens; title cleanup; frequency from repeat; due date from repeat when no date.
8. **Today maths** (`today.test.ts`): sections, sort (time, then priority, then position), completed-today by local day, `summarizeOpen`, reschedule targets.
9. **Streaks** (`streaks.test.ts`): kept = done before the next scheduled date; skips neutral; won't-do breaks; open occurrence past its window → 0; best streak; v2 history (late completions) counted as breaks.
10. **Core notifications additions** (`core/__tests__/notificationResponses.test.ts`): categories registered once and never in Expo Go; `schedule` passes `categoryIdentifier`; responses route by category, tap vs button, button taps dismiss the notification, the launch response is handled once (dedupe), a throwing handler is contained; `canNotify`.
11. **Task reminders** (`notifications.test.ts` in the module): `reminderDateFor` (date + time − offset, local, null when past/untimed/closed), body text, digest plan (7 days, projected counts, skip empty days, ids), resync registered.
12. **Hooks + api wiring**: `useToday`, `useTodos` (complete returns the successor for undo), reminder sync after writes, digest refresh debounced.
13. **Phone screens**: pager with Today first; Today sections + bulk Reschedule + collapsed Completed today + calm empty state with the next task; TaskRow (date chip, time, repeat rule, checklist progress, streak chip, long-press menu); undo toasts; quick-add sheet with chips; editor with time/reminder/notes/checklist/repeat editor/history; digest settings sheet. Navigation ref + response listener at the root.
14. **Home tile**: `summarizeOpen` line, tile opens Today (TodoList's default).
15. **Website**: Group by, overdue counts, quick add bar, calendar view, dialog parity, undo toast, skip action; Dashboard tile.
16. Full checks on both clients; report.

## Rulings

- Ruling: weekdays are stored 0 = Sunday … 6 = Saturday (JavaScript's `getDay`); weeks for "every N weeks" start on Monday — matches `Date` without a lookup and the Indian week the calendar already uses — cost if wrong: a stored-value remap in one migration.
- Ruling: "last day of the month" is stored as anchor day 31, since clamping 31 to each month's length is exactly the last day; the summary reads "on the last day" — one column fewer — cost if wrong: none observable; a separate flag could be added later.
- Ruling: nth weekday gets its own column, `repeat_nth` (1–4, −1 = last), with the weekday in `repeat_weekdays[0]`; no "5th Friday" — the spec's column list cannot express it otherwise, and a fifth weekday is missing in most months — cost if wrong: one more check value.
- Ruling: "repeat from completion" uses the interval only (completion date + N units, month-end clamped from that day) and ignores weekdays/nth/anchor — that is what "every 3 days after I last did it" means; Todoist's `every!` and TickTick's By Completion Date behave the same — cost if wrong: the editor hides options that would silently do nothing.
- Ruling: rolling forward lands on the first scheduled date strictly after today, so completing an overdue daily task today schedules tomorrow, never today (Todoist's documented behaviour) — cost if wrong: one extra tick on days you catch up late.
- Ruling: a repeating task always has a due date; turning repeat on with none (or quick-adding "every mon") sets the first scheduled date on or after today — otherwise there is nothing to roll forward from — cost if wrong: none; the date is editable.
- Ruling: weekly and monthly repeats store their weekday/anchor explicitly when saved, so rescheduling one occurrence never moves the schedule (rows from v2 without them fall back to the due date's weekday/day) — cost if wrong: a rescheduled legacy weekly task drifts to its new weekday until edited once.
- Ruling: the first occurrence of a new series has `series_id` null and every successor carries the first's id; the series key is `coalesce(series_id, id)` — no client-side UUIDs and no trigger to depend on — cost if wrong: queries use an `or(...)`, which is slightly slower than an equality.
- Ruling: the migration backfills `series_id` for v2 repeating rows by (user, trimmed lower-case title), so existing history has streaks on day one — v2 linked occurrences only by title — cost if wrong: two unrelated repeating tasks with the same title would share a history.
- Ruling: reopening deletes only *untouched* open occurrences of the same series (`updated_at = created_at`); one you edited is kept, even though that leaves two open — never delete what someone worked on — cost if wrong: an occasional duplicate to delete by hand.
- Ruling: priority resets to Normal on each new occurrence (kept from v2: urgency belongs to an instance); notes carry over; checklist items carry over unticked — the spec's "check items that reset when a repeat comes round" — cost if wrong: re-raising priority by hand.
- Ruling: "Skip" closes the occurrence with outcome `skipped` and creates the successor exactly as completing would; for from-completion rules the skip date counts as the completion date — cost if wrong: a skipped every-3-days task comes back 3 days after the skip rather than after the last real completion.
- Ruling: "Won't do" is offered in the long-press menu for one-off tasks only; for a repeat, Skip is the per-occurrence answer and stopping a routine is Edit → repeat off, or Delete — cost if wrong: one more menu item later.
- Ruling: streak = consecutive closed occurrences done before the next scheduled date after their due date; skips neither count nor break; won't-do breaks; an open occurrence whose window has passed makes the current streak 0; the chip shows from 2 — cost if wrong: a number that disagrees with intuition on edge days.
- Ruling: reminders need a due time; untimed tasks are covered by the daily digest — a reminder at an invented hour is a guess — cost if wrong: all-day tasks never buzz individually.
- Ruling: Snooze is 30 minutes, named on the button ("Snooze 30 min") — no settings screen exists to configure it — cost if wrong: a constant to change.
- Ruling: Done and Snooze act from the notification shade without opening the app (`opensAppToForeground: false`). If Android has killed the app's process, there is no JavaScript to run until the next launch; the response is then applied at launch (only the latest one survives). No dependency was added to get a headless task (expo-task-manager) — cost if wrong: a Done tapped on a cold phone takes effect when the app is next opened.
- Ruling: the digest is off until turned on in the Today view's bell sheet (turning it on asks for permission; never at launch). It is scheduled as dated notifications for the next 7 days with projected counts (rebuilt at launch and after changes); a day with nothing overdue or due gets no digest — a fixed daily trigger cannot carry today's counts — cost if wrong: counts go stale if the app is not opened for days, and website changes reach the digest only at the next launch.
- Ruling: digest settings are per device (AsyncStorage), because notifications are per device — cost if wrong: set it again on a new phone.
- Ruling: quick-add weekday names mean the nearest on or after today ("fri" on a Friday is today); "next fri" is Friday of next calendar week; a time with no date is today if still ahead, otherwise tomorrow; a bare "at 7" is whichever of 07:00/19:00 comes next (TickTick's nearest-future rule) — cost if wrong: one tap on the chip to undo it.
- Ruling: dates are day-first; dots mean a date only with a year (19.10.2026) and a time only with am/pm or after "at" (7.30pm), because "1.10" is as often a version as a date — cost if wrong: "19.10" stays text.
- Ruling: in quick add the first token of each kind wins and later ones stay in the title; a tapped (rejected) token is remembered by its text until the sheet closes — cost if wrong: a second date word in a title stays literal.
- Ruling: one-off tasks quick-added from Today are filed under Daily with today's date; from a frequency tab they take that tab and no date — every task still needs a tab — cost if wrong: refile on the web board.
- Ruling: the Open/Completed switch moves from the screen header into each frequency page; Today has its own collapsed "Completed today" — a header control that does nothing on the default page is noise — cost if wrong: one extra tap to see a tab's history.
- Ruling: "Completed today" counts occurrences closed today (done or skipped) by the local day of `completed_at` — cost if wrong: a skip shows as closed rather than hidden.
- Ruling: delete still asks to confirm — Tasks has no trash, so deleting is permanent; history rows of a series are untouched — cost if wrong: one extra tap.
- Ruling: website drag-and-drop works only when grouped by Frequency; Due and Priority groupings are read views with the same card actions — a drop onto "This week" has no single right date — cost if wrong: re-prioritising by drag is not available.
- Ruling: no "Ends: on date / after N times" — not in the spec — cost if wrong: end a routine by deleting or turning repeat off.
