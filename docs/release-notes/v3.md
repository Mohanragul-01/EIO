# EIO v3.0.0 — release notes

What v3 is, module by module, is in the [user guide](../USER-GUIDE.md) (start
with "What's new in v3"). This file is the release's record: how to install
it, what could not be checked without your phone or your database, the
decisions taken on your behalf while building it, and the small things left
for later.

## Installing

1. **Run the migrations** in `supabase/migrations/` through the Supabase SQL
   Editor. With 0001-0007 and 0009-0016 already in place from v2, run, in this
   order: **0017, 0018, 0008, 0019, 0020, 0021, 0022, 0023, 0024, 0025, 0026.**
   `0008_finance_v2.sql` belongs in the middle: v3's accounts need it, and
   0022 and 0023 build on it. Each file only adds, and each is safe to run
   twice. None of them has been run against a real database yet.
2. **Install the v3 APK straight away.** It replaces v2 on the phone (same
   signing key, so it installs over it and keeps you signed in).
3. **Open it once while signed in**, so the launch resync rebuilds every
   reminder with v3's buttons and exact timing.

Until the phone has v3, the old v2 app misreads the new data: its Products
screen crashes once a spare exists, it counts a transfer twice in its balance,
and an edit it makes to a subscription's cycle or date is misread. Keep the
gap between steps 1 and 2 to minutes, and don't create spares or transfers on
the website until the phone has v3.

  `eslint src App.tsx` clean.
- Website: `tsc -b`, `eslint src` and `vite build` clean. Browser behaviour of

  Important finding was fixed with a test that failed first (layout, colour
  and SQL-only fixes excepted, and marked so in their commits).

## Not verified without your phone or database

- **The migrations** (no database access during the build), including 0023's
  price-history ownership policies and the paged reads against real
  PostgREST.
- **Notifications on the APK**: the buttons (Done/Snooze, Mark paid, Keep it /
  I cancelled, Ordered / In 3 days) showing and opening the app; a press made
  while Android had killed EIO being handled once at launch; exact timing;
  reminders already in the tray from v2 keeping their old behaviour until the
  first resync.
- **On-screen look**: light and dark, the new 48dp targets, the Fitness level
  chip, step chart and hold-timer pulses, "TODAY" fitting the Subscriptions
  strip, TalkBack.
- **Timestamps on Hermes**: every database timestamp is now parsed by hand
  (`timestampMs`), so this no longer depends on the engine either way.

## Decisions taken on your behalf

Each is a call made where the spec was silent or two things conflicted, with what it costs if it was the wrong call. Verbatim from the build ledgers.


### Foundation (shared core) (24)

- **Setup** — work on branch v3 in the main checkout, not a separate worktree — isolation exists to keep main (what the installed APK was built from) clean, and a branch does that; a worktree needs its own node_modules for two projects — cost if wrong: none to main; v3 merges back when done.
- **Setup** — added .superpowers/ to .gitignore — the skill assumes the workspace is ignored and it was not — cost if wrong: none.
- **Task 1** — expo-doctor failed on 6 upstream patch releases (not this change); ran `npx expo install --fix` — patches within one SDK are Expo's compatibility promise and the next APK should carry them; reanimated/worklets re-verified unchanged — cost if wrong: a patch regression, visible in the next build.
- **Task 2** — website light --text-muted also failed (4.37:1) and fixing faint alone left no room below muted; stepped muted down to #686876 too — the spec requires 4.5:1 for normal text and the hierarchy needs three steps — cost if wrong: muted reads slightly darker on the website.
- **Task 2** — website contrast measured against background/surface/surface-2, not surface-3 — surface-3 is a hover/selected tint where secondary-or-stronger text sits; muted was additionally required to pass on surface-3 because the selected stat-button puts a muted label there — cost if wrong: faint text placed on a hover surface would read at ~4.3:1.
- **Task 4** — added `initialToastState` export and narrowed the live toast's `durationMs` to required — the tests need a starting state and the timer needs a number; both are additive to the plan's Interfaces — cost if wrong: none.
- **Task 4** — the toast pill is dark in both themes and its action uses the dark palette's primary, not the theme's `primary` — the light primary on a dark pill is about 3:1; an inverse snackbar is the platform convention (app: text 13.5, action 5.5; web: 14.2, 7.3) — cost if wrong: the toast looks the same in both themes.
- **Task 4** — the website toast pauses its timer while hovered or focused (not in the plan) — WCAG 2.2.1, and a desktop user reaches Undo with a pointer — cost if wrong: a toast stays up while the cursor rests on it.
- **Task 4** — a toast raised while an RN Modal (Sheet) or a web <dialog> is open draws beneath it — both are separate top-level layers; a flow that deletes from inside a sheet should close the sheet first, then toast — cost if wrong: an Undo hidden until the sheet closes, while its timer runs. Module builders must be told.
- **Task 5** — the "Today" button jumps to the current month but does not select today, and is disabled while that month is showing — selecting would fire onSelect, which a module may wire to open a sheet — cost if wrong: one extra tap to select today.
- **Task 5** — website day cells are 40px tall, not 44 — the 44dp floor is a touch rule and the site is used with a pointer; the app's cells are 46dp — cost if wrong: slightly small targets on a touchscreen laptop.
- **Task 5** — added a test that a month's days are consecutive (DST safety) beyond the brief's list — the build creates each day from (y, m, d) and the test pins it, though Jest's timezone may have no DST — cost if wrong: none.
- **Task 6** — `schedule` resolves a boolean (whether a reminder now exists), not void — scheduleReminder's existing contract returns that and could not compute it otherwise — cost if wrong: none, callers may ignore it.
- **Task 6** — `schedule` takes an optional `channel` (default 'reminders') and Subscriptions passes its existing 'renewals' channel — a new channel id would orphan the old one in Android Settings with the person's choices on it — cost if wrong: one extra channel in Settings.
- **Task 6** — `runResync` runs nothing when permission is not granted, and never prompts — each resync reads the database for reminders the phone would not show, and a launch prompt is the one people refuse — cost if wrong: after granting permission mid-session, reminders rebuild on the next launch rather than now.
- **Task 6** — no module registers a resync yet — rebuilding a module's reminders is that module's work (§8 Subscriptions, §5 Tasks); the core and the launch call are in place — cost if wrong: reminders are still lost on reinstall until those modules land.
- **Task 6** — the Sheet does not support drag-to-dismiss — the grabber is a signpost; backdrop, close and Back all dismiss, and a drag would compete with scroll inside the sheet — cost if wrong: one gesture people may try.
- **Task 6** — the brief's Step 7 listed only app checks; the website typecheck (which compiles shared app code) failed on getAllScheduledNotificationsAsync and was caught after task-done — fixed in a follow-up commit (website tsc RED→GREEN, eslint and vite build clean) — cost if wrong: none now; the lesson is to run both clients' checks on every task that touches shared code.
- **Final** — re-graded Minor 1 (dark-mode toast 1.28:1 against the canvas, raw hex) to Important — an Undo nobody notices in the default theme defeats the toast, and raw hex breaks spec §2 — fixed with inverse tokens.
- **Final** — fixed the cheap Minors (TalkBack announce + re-animate on replace, calendar dayLabel/48dp/8dp gap/live title/consistent styling, sheet subtitle one line, App.tsx comment, toast rises with keyboard, website Ctrl/Cmd+Z, real DST test) instead of deferring — the user's standing instruction is to leave no bug, and each is cheaper now than after seven modules consume these pieces — cost if wrong: a few extra lines.
- **Final** — kept the sheet drag but only on the grabber/title strip (reviewer's suggestion) — it no longer competes with scrolling — cost if wrong: none.
- **Final** — faint vs muted nearly identical is a spec consequence (both must be >= 4.5:1); faint stays a separate token whose difference is carried by use (size/placement) — cost if wrong: one fewer visible text step.
- **Final** — AccessibilityInfo.getRecommendedTimeoutMillis not adopted — toasts already pause nothing on the phone but are announced in full; revisit if the user ever uses TalkBack — cost if wrong: a screen-reader user may have less time for Undo.
- **Final** — PickerSheet duplication → Fitness work (F6 replaces it with core Sheet); Modal translucency moved unchanged; exact-alarm timing, schedule() true without permission (callers ensurePermission first), overlapping resyncs on user switch (single user), durationMs unclamped, throwing onAction (caller's job), Undo dropped during 140ms fade (at-most-once holds), app toast motion under reduced motion (opacity + 12dp only), web hover-under-still-pointer, unused keep-awake/speech (Fitness uses them), @types/react-test-renderer upstream, Hermes weekday:'narrow' (device check) — all stand as reviewed.
